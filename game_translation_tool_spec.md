# Спецификация проекта: LocKit

## 1. Концепт и Целевая аудитория
LocKit — это легковесный, высокопроизводительный десктопный инструмент для локализации инди-игр с глубокой интеграцией искусственного интеллекта (LLM). В отличие от устаревших решений (например, Translator++ на базе NW.js), проект изначально спроектирован для работы с огромными текстовыми базами (более 100 000 строк) без задержек интерфейса и с минимальным потреблением оперативной памяти.

### Целевые пользователи
* Переводчики-любители и профессиональные локализаторы инди-игр.
* Моддеры, создающие фанатские переводы.
* Инди-разработчики, желающие автоматизировать перевод своих проектов.

### Поддерживаемые устройства и ОС
* Windows (основной приоритет, запуск в виде единого компактного EXE-файла или инсталлятора).
* Linux и macOS (полная кроссплатформенность интерфейса и логики).

## 2. Выбранный стек технологий
Для обеспечения максимальной стабильности, производительности и простоты дистрибуции выбран следующий стек:

* **Интерфейс (Frontend):** C# .NET 9 + **Avalonia UI** (сборка через Native AOT).
  * Обеспечивает плавную работу интерфейса за счет рендеринга через Skia/Angle напрямую на GPU.
  * Полностью исключает HTML/JS/CSS и веб-движки, что экономит сотни мегабайт оперативной памяти.
* **Бэкенд и логика парсинга:**
  * **C# (.NET 9):** Управление жизненным циклом приложения, интерфейс, локальная база данных, асинхронные запросы к API ИИ.
  * **Rust Core (через FFI / PInvoke):** Низкоуровневый разбор сложных бинарных форматов игровых архивов. Rust компилируется в статическую библиотеку (`.a` / `.lib`), функции которой вызываются из C#.
* **База данных (Локальное хранилище):** SQLite (через `Microsoft.Data.Sqlite` или `Entity Framework Core`). Хранит проекты перевода, базу памяти переводов (Translation Memory) и глоссарии.
* **Сборка и дистрибуция:** Сборка с параметром `PublishAot=true` и триммингом кода. Готовое приложение поставляется как один независимый исполняемый файл размером около 11 МБ (сжатый через UPX) и потребляет около 140 МБ RAM в простое.

## 3. Коммерциализация и Лицензирование (Задел под монетизацию)
При проектировании учитывается возможность выпуска закрытой коммерческой версии ПО:

* **Лицензирование UI:** Используются только компоненты под лицензией MIT. Элемент виртуализации **ItemsRepeater** полностью бесплатен для любого коммерческого использования. Избегаем использования компонента `TreeDataGrid` (начиная с версии Avalonia 12 он требует платной лицензии Avalonia Pro для закрытых коммерческих проектов).
* **Библиотеки парсинга:** Все используемые внешние крейты Rust (например, `marshal-rs`, `wolfrpg-map-parser`) и NuGet-пакеты C# подбираются строго с пермиссивными лицензиями (MIT, Apache 2.0 или BSD). Использование GPL-кода исключается.
* **Защита кода:** Native AOT компиляция транслирует C# код напрямую в машинные инструкции (ассемблер) вместо стандартного IL-кода. Это значительно затрудняет декомпиляцию и реверс-инжиниринг по сравнению с обычными приложениями на C# или Java/JS.

## 4. Функциональные требования

### 4.1. Импорт и экспорт игровых форматов
Приложение должно уметь извлекать текст из игровых ресурсов, отображать его в удобной таблице для перевода и записывать обратно без повреждения структуры игры.

* **Ren'Py (Минимум для MVP):**
  * Чтение сценариев сценариев `.rpy` (простой текстовый формат с разметкой диалогов и кода).
  * Извлечение текстов из архивов `.rpa` (используя библиотеку на Rust).
  * Сохранение перевода в файлы локализации Ren'Py с сохранением структуры тегов.
* **RPG Maker (XP, VX, VX Ace, MV, MZ):**
  * Для MV/MZ: парсинг файлов диалогов и карт в формате JSON.
  * Для XP/VX/VX Ace: чтение бинарных файлов сериализации Ruby Marshal (`.rxdata`, `.rvdata`, `.rvdata2`). Логика десериализации выносится в Rust (библиотека `marshal-rs` и `rvpacker-txt-rs-lib`).
* **Wolf RPG Editor:**
  * Чтение карт `.mps` и общих событий. Разбор бинарной структуры выносится в Rust (библиотека `wolfrpg-map-parser`).
* **Unity:**
  * Чтение и запись текстовых ресурсов, сериализованных файлов и AssetBundles с использованием C# библиотек (таких как `AssetRipper`).

### 4.2. Автоматизация перевода с помощью ИИ
Основной упор делается на качественный перевод силами современных LLM, а не простое машинное сопоставление слов.

* **Агрегатор API:** Поддержка подключения к любым провайдерам (Gemini API, OpenAI API, Anthropic, а также локальным моделям через Ollama).
* **Гибкая настройка:** Пользователь может указать в настройках:
  * API Key
  * Model Name
  * Base URL (для работы с прокси или локальными серверами)
  * Кастомный системный промпт (например, задающий стиль речи персонажей).
* **Передача контекста:** ИИ получает не просто отдельные строки, а батчи (пакеты строк) вместе с метаданными:
  * Глоссарий текущего проекта (ИИ обязуется переводить термины строго по словарю).
  * Описание персонажей (пол, возраст, характер).
  * Контекст соседних строк (история диалога) для сохранения правильного рода и обращений.
* **Структурированный вывод (Structured Outputs):** Использование формата JSON Schema при запросах к ИИ, чтобы гарантировать возврат переводов, строго привязанных к исходным ID строк.
* **Интерактивный помощник:** Встроенный локальный агент-помощник, который помогает пользователю составить эффективный промпт для конкретной игры, настроить API и оптимизировать расходы на токены.

### 4.3. Память переводов (Translation Memory) и Глоссарий
* **Глоссарий:** Словарь фиксированных терминов (имена персонажей, названия предметов, локаций), который автоматически подставляется или передается в ИИ.
* **Память переводов (TM):** Локальная база данных всех выполненных переводов. При появлении похожей строки система вычисляет процент совпадения (расстояние Левенштейна).
* **Фоновые вычисления:** Расчет схожести строк выполняется строго в фоновых потоках C#, чтобы интерфейс прокрутки не зависал.

## 5. Архитектура и оптимизация интерфейса

### 5.1. Виртуализация таблицы (100k+ строк)
Для отображения строк используется виртуализированный список. В Avalonia UI это реализуется с помощью элемента `ItemsRepeater`, помещенного внутрь `ScrollViewer`, что гарантирует плавность интерфейса и отсутствие утечек памяти.

**Правило оптимизации визуального дерева:**
Для экономии памяти и ресурсов процессора ячейка таблицы в режиме чтения отображается как простой легковесный `TextBlock`. Интерактивное поле редактирования (`TextBox`) создается в визуальном дереве динамически только тогда, когда пользователь дважды кликает на ячейку для редактирования, и полностью уничтожается при потере фокуса.

### 5.2. Интеграция Rust через FFI
Схема взаимодействия между C# (UI) и Rust (Парсер):

1. Разбор бинарных файлов (например, RPG Maker `.rvdata2` или архивов Wolf RPG) инициируется из C#.
2. C# вызывает метод из скомпилированной Rust-библиотеки через P/Invoke, передавая пути к файлам.
3. Rust быстро распаковывает бинарные структуры, преобразует текст в промежуточный JSON или CSV и возвращает управление C#.
4. C# импортирует полученные данные в SQLite базу данных проекта.

Пример декларации вызова на стороне C#:
```csharp
using System.Runtime.InteropServices;

public static class NativeParser
{
    [DllImport("rpgm_parser_ffi", CallingConvention = CallingConvention.Cdecl, CharSet = CharSet.Ansi)]
    public static extern int parse_rpg_maker_vxace(string inputDir, string outputDir);
}
```

## 6. Сборка и Упаковка (Инсталлятор)
Для конечных пользователей распространение в виде сырого `.exe` файла может казаться менее привычным и надежным, поэтому проект собирается в двух вариантах:

1. **Portable-версия:** Один скомпилированный EXE-файл (после Native AOT публикации и сжатия через UPX весит около 11 МБ).
2. **Классический установщик (Installer):**
   * Для сборки установщика используется бесплатная утилита **Inno Setup**.
   * Inno Setup упаковывает скомпилированный бинарный файл, необходимые локальные ресурсы и базу данных в один удобный установочный файл (например, `LocKit_Setup.exe`).
   * Инсталлятор автоматически создает ярлыки на Рабочем столе и в меню «Пуск», регистрирует приложение в системе для удобного удаления и позволяет ассоциировать проектные файлы программы (например, `.lkproj`) с LocKit.
